# Brainstorm：需求收敛器

从任意规模、任意复杂度的需求出发，产出一份完整 Spec 文件，衔接 /todo 做任务拆解。

## 成功的定义

> 产出一份 Spec 文件（写入 `$PROJECT_DIR/data/todo/{name}.md`），满足：
> 1. 覆盖需求涉及的所有模块和交互——没有因为信息不足而遗漏
> 2. 挑战过需求本身的前提——不是在错误的问题上做完美的分析
> 3. 对比过替代方案——不是第一个想到什么就做什么
> 4. /todo 仅凭此文件就能拆解出可执行的原子任务

<HARD-GATE>
在 Spec 文件写入且用户确认之前，不允许：
- 写任何实现代码
- 创建任何实现文件
- 调用 /todo、/vibe 或任何实现类命令（它们是本 skill 之外的后续流程）
- 给出可以直接复制粘贴的代码实现

你可以讨论技术方向、架构选择、方案的技术可行性——但不写具体代码。

所有需求都适用，无论看起来多简单。一个配置改动、一个小工具、一个"只是加个字段"——全部。"简单"需求恰恰是未经检验的假设造成最多返工的地方。Spec 可以短（几句话），但必须经过前提挑战和用户确认。
</HARD-GATE>

## 三条路线

| 路线 | 什么时候走 | 怎么收集信息 |
|------|-----------|-------------|
| **快速** | 涉及 1-2 个模块，描述明确，无跨模块耦合 | 跳过深度收集，直接聚焦提问 |
| **深潜** | 3-5 个模块，中等模糊度，有跨模块交互 | 单 agent 自底向上 + 自顶向下深度收集 |
| **围猎** | >5 个模块，高耦合，或"漏一个就失败"的完备性压力 | 多 agent 并行收集，交叉验证，缺口扫描 |

## 进入

用户可以直接指定路线跳过校准：
- `/brainstorm quick [需求]`
- `/brainstorm deep [需求]`
- `/brainstorm hunt [需求]`
- `/brainstorm [需求]` → 自动校准

**读取 `calibrate.md` 开始。** 按阶段分步加载、分步执行：

1. **探查 & 校准**（`calibrate.md`）— 扫描项目，确定路线
2. **发散**（`diverge-deep.md` 或 `diverge-hunt.md`）— 深潜/围猎路线的信息收集。快速路线跳过
3. **收敛**（`converge.md`）— 提问、前提挑战、方案对比
4. **Spec**（`spec-write.md`）— 写入文件、自检、衔接 /todo

**在当前阶段完成并获得用户确认之前，不要读取下一阶段的文件。**

<RATIONALIZATION-PREVENTION>
你会想跳过步骤的理由，以及为什么不能跳：

| 你会想的 | 现实 |
|----------|------|
| "用户已经想清楚了，不需要前提挑战" | 用户认为想清楚了 ≠ 真的想清楚了。未经挑战的假设是返工的头号来源 |
| "只有一种实现方式，没法对比" | 几乎不存在"只有一种方式"。至少可以对比"最小实现" vs "完整实现"的范围取舍 |
| "前提挑战会让用户觉得我在质疑他" | 你不是在质疑用户的判断，你是在帮他检查盲点 |
| "探查已经够了，不需要深度收集" | 探查是画地图，收集是实地勘测。地图上看着小的区域实地可能很复杂 |
</RATIONALIZATION-PREVENTION>
