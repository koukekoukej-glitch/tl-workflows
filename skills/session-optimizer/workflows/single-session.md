# 单 Session 分析工作流

> 前置条件：已完成 SKILL.md 中的 Phase 1（理解 Agent 身份）。

---

## Step 1：加载 Session 素材

1. 运行 `node server/scripts/extract-metrics.js <id>` 获取指标概览和轮次摘要
2. 读 `data/session_cases/conv-<id>.md`（不存在则先 `node server/scripts/export-session.js <id>`）
3. **大报告（>2000 行）**：先用 metrics 脚本定位问题轮次，只读相关轮次（Grep 搜 `### 轮次 N` 定位行号，用 offset+limit 读取）
4. **检查数据完备性**：报告开头的"数据完备性"章节说明了哪些数据被截断。对关键决策点涉及的截断工具返回，用 `input_json` 重放还原完整结果后再做归因。

## Step 2：第一视角还原

这是单 Session 分析的核心。

**第一步：还原 Agent 的信息状态。**
从报告的工具调用链中，逐一读取 Agent 实际 Read 过的文件——让自己处于和 Agent 相同的信息状态。

**第二步：在每个关键决策点分析。**
关键决策点 = 路由选择、策略切换、工具选择、结论生成。对每个决策点：

1. **Agent 此时看到了什么？** 已加载的文件 + 前序工具调用的返回结果
2. **Agent 做了什么选择？** 调用了什么工具、传了什么参数
3. **基于它当时的信息，这个选择合理吗？**
4. **如果不合理，根因是什么？**
   - **信息缺失**：关键信息不在 Agent 已加载的任何文件中
   - **信息误导**：某条信息引导 Agent 走向错误方向
   - **暴露时序错误**：信息在错误的阶段出现，诱导跳步
   - **信息冗余**：模型能自行发现的信息占据上下文，干扰决策
   - **推理偏差**：信息充分但 Agent 仍判断错误（修改上下文帮助有限）

> **SDK 约束排除**：Agent 的失败如果是因为工具不可用或路径受限，这是 SDK 配置问题，不归因到上下文工程。参考 `references/harness-profile.md` 确认约束边界。

## Step 3：评估最终结果

1. Agent 的最终交付是否正确、完整？
2. Agent 走的路径是否是最短路径？如果不是，**理想路径是什么**？
3. 有没有超出上下文预期的行为？

## Step 4：归因过滤

加载 `references/core-methodology.md`。对 Step 2-3 中识别的每个偏离点，**先过滤再生成方案**。

### 4a. 逐偏离点过滤（全部通过才进入方案生成）

1. **这是上下文工程问题吗？**
   - 工具性能（超时、崩溃）→ SDK/工具侧问题，记录但不生成上下文方案
   - 模型推理偏差（信息充分但判断错误）→ 上下文工程帮助有限，记录但不生成方案
   - 信息缺失/误导/时序错误/冗余 → 继续下一步

2. **缺失的信息正交吗？**
   - 回到报告，找 Agent **实际的工具调用**——它搜了什么关键词、读了什么文件？
   - 如果 Agent 已经自行找到了相关概念（只是花了更多步），说明信息不正交，淘汰
   - 只有模型用已有工具**无法在合理步数内自行发现**的信息才正交（跨层桥接、魔法数字语义、反知识）

3. **信息该放在哪？**
   - 已有模块文档能承载 → 补进对应文档
   - 没有合适位置 → 才考虑新建，但必须论证新文档和同层文档是**同一粒度**（不能把跨系统的管道当成独立模块）

### 4b. 方案生成（只处理通过过滤的偏离点）

对每个通过过滤的偏离点：

1. **用根因分类定位**：是内容层问题还是架构层问题？补丁还是重构？
2. **用四重检验评估**：拟修改的信息是否满足正交性 + 时机 + 位置 + 长期有效？
3. **反过拟合检查**：方法论/规则变更需要 ≥2 session 支持，事实补充可以单 session

## Step 5：产出

### 分析报告

```markdown
## Session 分析：Conv <id>

### Agent 使命与理想路径
[基于 CLAUDE.md 的理解，这类问题的理想处理路径]

### 实际发生了什么
[第一视角还原的关键发现，标注报告中的精确位置（轮次、调用序号）]

### 偏离分析
[Agent 在哪些决策点偏离了理想路径，每个偏离的根因]

### 上下文工程审视
[从案例上升到结构层面的启发]

### 正面发现
[Agent 做得好的地方，不应被破坏]

### 优化方案
| # | 改动 | 类型 | 四重检验 | 预期行为变化 |
|---|------|------|---------|-------------|
| 1 | [描述] | 事实补充/结构改进 | 正交✓ 时机✓ 位置✓ 长期✓ | [同类场景下的行为变化] |
```

**等待用户确认后再执行修改。**

### 指标存档

| 指标 | 提取方式 | 说明 |
|------|---------|------|
| 总工具调用数 | metrics 脚本 | 主代理/子代理分别统计 |
| 失败调用数 | `is_error = 1` | 主代理/子代理分别统计 |
| 总费用 | 报告费用统计 | replay 对比基线 |
| 总耗时 | 首尾工具调用时间差 | replay 对比基线 |
| 用户纠错轮次 | 手工计数 | 0 为理想 |

### 执行修改（用户确认后）

- **CWD side**: Modify files in Agent working directory using absolute paths
- **SDK 侧**：修改本项目源码
- 修改后对照四重检验做最终确认

### 归因纪律

- 每个因果归因必须指向报告中的精确位置（轮次号、工具调用序号）
- 如果报告中有上下文压缩标记（compact），区分压缩前后的行为差异
